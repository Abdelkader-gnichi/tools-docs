## Introduction to USP and `obuspa`

The **User Services Platform (USP)** is a protocol defined by the Broadband Forum (TR-369) for managing, monitoring, and controlling connected devices. It is the successor to the popular TR-069 (CWMP) protocol.

`obuspa` is an open-source USP agent designed to run on embedded systems like those powered by **OpenWrt**. It acts as the bridge between a USP Controller (a remote management server) and the device's data model, allowing for powerful, standardized remote operations.

## Managing the `obuspa` Service

The `obuspa` agent is managed as a standard OpenWrt `init.d` service.

**Stopping the agent:**
To terminate the running `obuspa` process:
```bash
/etc/init.d/obuspa start
```

**Restarting the agent:**
To apply new configurations or restart the service:
```bash
/etc/init.d/obuspa restart
```

**Stopping the agent:**
To stop the service:
```bash
/etc/init.d/obuspa stop
```

**Verifying the agent's status:**
You can check if the `obuspa` process is active using `ps`:
```bash
ps | grep obuspa
```
A successful output will show the running `obuspa` process.

## Configuration Files

The `obuspa` agent relies on two key configuration files when run as a service.

### Primary Configuration: `/etc/config/obuspa`

This is the main configuration file that you should edit. It uses the standard UCI (Unified Configuration Interface) format of OpenWrt. The `init.d` script reads this file to generate the final configuration used by the agent.

**Example `/etc/config/obuspa`:**

```lua
config global
	option interface 'wan'
	option StartTime '11:05:25'

config controller
	option Alias 'cpe-1'
	option Enable 'true'
	option EndpointID 'proto::rx_usp_agent_mqtt'
	option AssignedRole 'Device.LocalAgent.ControllerTrust.Role.1'
	# ... other controller options

config controller_mtp 'mtp_test'
	option Enable 'true'
	option Protocol 'MQTT'
	option MQTT_Reference 'Device.MQTT.Client.1'
	option MQTT_Topic '/usp/admin/controller'
	# ... other MTP options

config mtp
	option Alias 'cpe-1'
	option Enable 'true'
	option Protocol 'MQTT'
	option MQTT_Reference 'Device.MQTT.Client.1'
	option MQTT_ResponseTopicConfigured '/usp/admin/endpoint'

config mqtt
	option Alias 'cpe-1'
	option Enable 'true'
	option BrokerAddress 'mqtt.eclipse.org'
	option BrokerPort '1883'
	option Username 'username'
	option Password 'password'
	option KeepAliveTime '60'
	option ProtocolVersion '5.0'
	# ... other MQTT options

config subscription
	option Enable 'true'
	option Recipient 'Device.LocalAgent.Controller.1'
	option ID 'default-boot-event-ACS'
	option NotifType 'Event'
	option ReferenceList 'Device.Boot!'
	option Persistent 'true'
```

This file defines all necessary parameters, including the controller's endpoint ID, MTP (Message Transfer Protocol) settings, MQTT broker details, and event subscriptions.

### Generated Configuration: `/tmp/obuspa.conf`

**Important:** Do not edit this file directly. It is automatically generated by the `/etc/init.d/obuspa` script based on the settings in `/etc/config/obuspa`.

This file translates the UCI format into the flat data model parameter format that the `obuspa` binary understands. It is useful for verifying that your UCI configuration is being parsed correctly.

**Example `/tmp/obuspa.conf`:**
```
Device.LocalAgent.Controller.1.Alias "cpe-1"
Device.LocalAgent.Controller.1.Enable "true"
Device.LocalAgent.Controller.1.EndpointID "proto::rx_usp_agent_mqtt"
Device.LocalAgent.Controller.1.AssignedRole "Device.LocalAgent.ControllerTrust.Role.1"
Device.LocalAgent.Controller.1.PeriodicNotifInterval "86400"
# ... (rest of the parameters)
Device.MQTT.Client.1.Enable "true"
Device.MQTT.Client.1.BrokerAddress "mqtt.eclipse.org"
Device.MQTT.Client.1.BrokerPort "1883"
# ...
Device.LocalAgent.Subscription.1.Enable "true"
Device.LocalAgent.Subscription.1.Recipient "Device.LocalAgent.Controller.1"
Device.LocalAgent.Subscription.1.ID "default-boot-event-ACS"
Device.LocalAgent.Subscription.1.ReferenceList "Device.Boot!"
```

## Running `obuspa` Manually for Debugging

For troubleshooting, it's often useful to run the agent directly from the command line to see verbose log output.

1.  **Create a configuration file** (e.g., `mqtt`):
```
Device.LocalAgent.EndpointID "AG_device"
Device.LocalAgent.Controller.1.BootParameter.1.Enable true
Device.LocalAgent.Controller.1.BootParameter.1.ParameterName "Device.LocalAgent.EndpointID"
Device.LocalAgent.Subscription.1.Alias cpe-1
Device.LocalAgent.Subscription.1.Enable true
Device.LocalAgent.Subscription.1.ID default-boot-event-ACS
Device.LocalAgent.Subscription.1.Recipient Device.LocalAgent.Controller.1
Device.LocalAgent.Subscription.1.NotifType Event
Device.LocalAgent.Subscription.1.ReferenceList Device.Boot!
Device.LocalAgent.Subscription.1.Persistent true
Device.LocalAgent.MTP.1.MQTT.ResponseTopicConfigured "easy/usp/v1/controller"
Device.LocalAgent.MTP.1.MQTT.Reference "Device.MQTT.Client.1"
Device.MQTT.Client.1.BrokerAddress "192.168.100.71"
Device.MQTT.Client.1.ProtocolVersion "5.0"
Device.MQTT.Client.1.BrokerPort "1883"
Device.MQTT.Client.1.TransportProtocol "TCP/IP"
Device.MQTT.Client.1.Username ""
Device.MQTT.Client.1.Password ""
Device.MQTT.Client.1.Alias "cpe-1"
Device.MQTT.Client.1.Enable true
Device.MQTT.Client.1.ClientID ""
Device.MQTT.Client.1.KeepAliveTime "60"
Device.MQTT.Client.1.ConnectRetryTime "5"
Device.MQTT.Client.1.ConnectRetryIntervalMultiplier   "2000"
Device.MQTT.Client.1.ConnectRetryMaxInterval "60"
Device.LocalAgent.Controller.1.Alias "cpe-1"
Device.LocalAgent.Controller.1.Enable true
Device.LocalAgent.Controller.1.PeriodicNotifInterval "86400"
Device.LocalAgent.Controller.1.PeriodicNotifTime "0001-01-01T00:00:00Z"
Device.LocalAgent.Controller.1.ControllerCode ""
Device.LocalAgent.Controller.1.MTP.1.Alias "cpe-1"
Device.LocalAgent.Controller.1.MTP.1.Enable true
Device.LocalAgent.Controller.1.MTP.1.Protocol "MQTT"
Device.LocalAgent.Controller.1.EndpointID "easyController"
Device.LocalAgent.Controller.1.MTP.1.MQTT.Reference "Device.MQTT.Client.1"
Device.LocalAgent.Controller.1.MTP.1.MQTT.Topic "easy/usp/v1/controller"
Device.LocalAgent.MTP.1.Alias "cpe-1"
Device.LocalAgent.MTP.1.Enable true
Device.LocalAgent.MTP.1.Protocol "MQTT"
Internal.Reboot.Cause "LocalFactoryReset"
```
2.  **Run `obuspa` with the custom file (mqtt)**

```bash
/usr/sbin/obuspa -p -v 4 -r mqtt -i eth0.2
```
*   `-p`: Run in persistent mode (as a daemon).
*   `-v 4`: Set verbosity level to 4 for detailed logging.
*   `-r mqtt`: Use MQTT as the MTP.
*   `-i eth0.2`: Bind to the `eth0.2` network interface (typically WAN).

**Modifying the WAN IP Address:**
The `obuspa` agent often needs to bind to the correct WAN interface. If you need to change the device's IP:

1.  **Edit the network configuration file:**
    ```bash
    vi /etc/config/network
    ```
2.  In the `config interface 'wan'` section, update the desired IP address or protocol.
3.  **Restart the network service** to apply the IP change.
```bash
/etc/init.d/network restart
```
4.  **Stop the `obuspa` agent init.d mode** to ensure that only one obuspa instance is running when running it in debug mode:
```bash
/etc/init.d/obuspa stop
```
5.  **Re-Run the `obuspa` agent in debug mode** to ensure it uses the new network settings:
```bash
/usr/sbin/obuspa -p -v 4 -r mqtt -i eth0.2
```

## Resetting the Agent Database

The `obuspa` agent maintains its state, including dynamic configurations pushed by a controller, in a database file. To perform a factory reset of the agent's configuration:

1.  **Stop the agent:**
    ```bash
    /etc/init.d/obuspa stop
    ```
2.  **Remove the database file:**
    ```bash
    rm -rf /var/obuspa/usp.db
    ```
3.  **Start the agent again:**
    ```bash
    /etc/init.d/obuspa start
    ```
    The agent will recreate the database, loading its initial configuration from the `/etc/config/obuspa` file.
